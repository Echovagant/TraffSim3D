# ADR-012: 转弯从枢轴改为弧线 —— 车身不再瞬移扫过路口角

- **Status**: ✅ **Accepted** (2026-10-31)
- **Date**: 2026-10-31
- **Deciders**: Project lead（枢轴碰撞的几何根因）
- **Amends**: [ADR-010](ADR-010-route-planning-and-the-first-person-camera.md)
  里「转弯是枢轴、是模型 idiom」的适用边界

---

## Context

枢轴（pivot-in-place）是转弯的模型 idiom：车到行进末端，原地换到新车道、换朝向。
它的缺陷**自己记录过**（`roadTransition.ts` 的注释、ADR-010 的 Decision 末段）：
转弯车**瞬移**横扫路口角——来路车道与去路车道各离中线 5.25 m，直角转弯的车身
横扫最多 **7.4 m**——后车开进它留在角上的车身。实测（5×5 网格 90 s、
135 000 车辆帧）：**5 帧重叠、最深 0.271 m**。

两条看似能抓它的规则都被论证过不行（同注释）：让行规则保护「先到先走」的承诺
语义、跟车模型抓不到「挡路的是转弯车自己的车身」。结论一直是：**修法是弧线，
属于模型改动**。Scene 4 v2 要把协商扩到网格尺度——转弯更频繁——所以本轮做了
这次模型改动。

## Decision

**转弯 = 二次贝塞尔弧**（`src/domain/services/roadTurnArc.ts`）：
从车辆**当前位姿**（P0，行进方向）到新车道**入口位姿**（P2，车道朝向），
控制点 P1 = 两条方向线的交点（角落）。弧按**距离**推进（速度归 ramp 照常），
朝向取弧的**解析切线**（二次贝塞尔的导数是线性的，端点精确——有限差分在端点
误差实测 5e-4 rad）。

三条支撑规则：

1. **落位语义**：`roadId / laneIndex / s / heading` 在**转弯开始时**就设为
   目标值（约束、让行、选中都看到车承诺去的那条路）；`Vehicle.turn` 携带弧的
   控制点与进度，推进中位姿从弧取；到长后**先把位姿吸到弧终点**再清 turn——
   否则落位帧的位姿还在弧中途、离车道点最远 ~7 m，5 m 车道护栏恰好会在
   落位帧触发（实测踩中）。
2. **近直行不进弧**（`MIN_ARC_TURN_RAD = 0.1`）：十字路口的直行 continuation
   会在**越过入口点之后**才检测到行进末端（过冲一帧的距离），此刻「从当前位姿
   到入口位姿」的弧是**向后**的——车会被往回拽、速度冻结（实测帧迹：11.83 →
   0.03）。近直行的 continuation 没有横向扫掠要修（枢轴碰撞全是直角弯），
   **直接落位**是既简单又正确的行为。
3. **两条运动路径同一个弧**：Rapier 路径的车身由弧 kinematically 拖动
   （applyControl 与 Pure Pursuit 对转弯中的车让位，body linvel 清零），
   物理无关路径按同一纯函数推进——**两路径的弧逐帧一致**（pathParity 8/8）。
   转弯中的速度 ramp 照常（应用层对实体做），弧长由速度消耗。

## Consequences

- **实测（真 Rapier、90 s、5×5 网格、67 辆）**：重叠帧 **5 → 0**，且
  `tick.turning.spec.ts` 把 `toBe(0)` 钉住——数字不能悄悄涨回去。
- **body 在转弯中是乘客**（linvel = 0，位姿由弧拖）——速度的真值在实体上，
  `readPose().speed` 在转弯中是 0。依赖 body 速度的断言/逻辑已随语义更新。
- **视觉基线未动**：弧线是瞬态（~1 s），场景冻结帧抓的是静态布局——
  48 项 e2e 全绿、无一张基线重录。
- **训练环境不变**：Python 侧的车辆是点（无车身），枢轴/弧线在那里无差别；
  本决策只属于浏览器的车道锁定模型。转弯中几帧的位姿与训练环境的瞬时转移
  有差——策略的观测在转弯中略有不同，实机行为（v1 场景零碰撞全通过）是
  它的鲁棒性证据。
- **序列化零改动**：`Vehicle.turn` 是可选字段，序列化整对象透传；
  转弯中保存场景会在恢复时丢失弧（车辆直接出现在入口点）——弧长 ~1 s，
  可接受。

## Alternatives considered

- **保持枢轴 + 加宽路口盒**：盒更宽只会让更多车被让行规则拦停、堵死路口 ⇒ 拒绝。
- **只插值朝向不插值位置**（枢轴的温和版）：横扫的几何还在，只是慢一点 ⇒ 拒绝。
- **转弯交给 Pure Pursuit**（像 `network_sim_core` 的连续模型）：浏览器是车道
  锁定模型，车没有「在车道外」的表达；弧线本质就是这条路的可序列化版本 ⇒ 等价，
  选了更简单的。
- **圆弧而不是贝塞尔**：对直角转弯等价，但贝塞尔对任意臂角与折线 waypoint
  都成立，且控制点构造更简单 ⇒ 选贝塞尔。

## Update (2026-10-31，弯道限速与跟车锥)

弧线落地后的两个补充（同一次模型改动的收尾）：

1. **弯道限速**：弧按**曲率半径**限速 `v = √(a_lat·R)`（`TURN_LAT_ACCEL = 2.5
   m/s²`，R = 弧长/转角）。直角弯 ≈ 17–20 km/h——不再是 60 km/h 甩过弯道。
   转弯中 `targetSpeed` 被封顶；**路线驱动车辆进弯预刹车**（刹车距离内 armed，
   实测 13.95 → 5.36 m/s 的教科书式进弯减速）。
2. **跟车锥兜底**：弧线中的车 roadId 已是目的地——同车道 leader 过滤会让它对
   后车**隐形**，后车全速撞进弧扫过的角（实测：限速后网格 110 帧重叠，首对
   车辆双双 "waiting" 在**同一条路**上）。修复：对弧线中的车用**空间锥**判定
   前车（正前方、一车道宽内），不看 roadId。修复后重叠帧回到 **0**。
