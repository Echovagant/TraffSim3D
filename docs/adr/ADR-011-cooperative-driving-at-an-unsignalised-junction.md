# ADR-011: 无信号路口的多车协商 —— 合作靠「挡人要付代价」，碰撞算在开动的车头上

## Context

Scene 3 把**信号灯 agent** 做成了真正的多智能体：25 个路口各跑一份观测、同一个 actor、
一个集中式 critic，训练出来的策略随产品附带、在浏览器里指挥 25 个路口。

但项目 §1.1 的另一半 —— **「学会开车」** —— 还只有单路口的单车 ego。路网尺度上
**没有多个「会开车」的智能体**：`multi_env.py` 是 N 个**互不交互**的独立路口
（各自一个路口，谁也碰不到谁），`network_sim_core.py` 是**一个**学习 ego 加四个脚本 NPC。

而真实路网里，无信号路口才是常态：**深圳导入路网 7991 个路口只有 51 个带信号灯**
⇒ 96 % 的路口没有相位可依，路权只能由**行为**协商。

「谁先过」于是是一个真正的合作问题：结果取决于**别人**怎么做，任何一个 driver 都无法
独自解决。

## Decision

**场景**：2–4 个驾驶者 + 少量背景车，在**没有信号灯**的路口相遇，学习让行与择机通行。
**协作进奖励的方式**：拥堵归因 —— 每辆车的奖励 = −（自己的延误 + **它直接挡住的那些车
的延误**），碰撞另计。**交付**：训练侧 + 权重 fixture + 实测报告（浏览器侧复用现有
replay 路径开一辆车）。

三条支撑它的规则：

1. **起点带方向**（沿用 ADR-010 的做法）：车不在路口上，它在一条路上、正朝那头去。
2. **转向是枢轴**（沿用浏览器 `roadTransition.ts` 的模型）：Pure Pursuit 单独转不过
   90° 弯（转弯半径 ~6 m < 换道横移 10.5 m），实测会把车切到 33 m 外、路网外的地方去。
3. **车辆靠右行驶**（横向偏移 5.25 m，与浏览器同口径）：否则同一条臂上的对向车走
   的是**同一条中线**，迎面撞是几何写死的，不是协商。

### 奖励为什么这样定

- **延误归因**是协作的来源：挡住别人的人要付别人等的代价 ⇒「一直开下去」不再免费。
- **碰撞罚在开动的车头上**：一次碰撞里，停着的那辆是受害者（本该让行却被撞），
  开着的那辆是肇事者。**两边同罚**会让策略分不清「我撞的」和「我被撞的」，
  梯度指向「别动」而不是「别开进有车的路口」。
- **碰撞必须比等待贵得多**：实测把「一次撞车」定价为 5（等一秒是 0.1）时，
  **谁都不让的基线反而回报最好**（−23.5 对右让规则的 −67.0）——目标函数在说反话。
  定为 20（一次撞车 = 20 秒等待）之后，排序才回到应有的样子。

### 两个基线是必需的

「学到的策略比瞎做强」不是结论。两个脚本基线在同一批 seed 上量：

| 基线 | 行为 |
|---|---|
| `always_go` | 谁都不让 |
| `right_of_way` | 先到先行，平局时**右侧先行**（经典规则），让行时**在路口盒外**刹住 |

实测（6 seed、3 个驾驶者）：`always_go` 撞 16 次、延误 3.1、18/18 通过；
`right_of_way` 撞 14 次、延误 56.6、**16/18 通过**（两辆循环等待卡死）。

## Consequences

- **第三套 sim core**：`drive_core.py`（23 维观测，多个学习 driver + 脚本车流 +
  延误归因）。它**不导入** `sim_core.py`（契约核），与 `network_sim_core.py` 一样是
  独立命名空间；`tests/test_rl_drive_core.py` 守住这条。
- **策略可导出成浏览器能吃的权重**：actor 的层名就是浏览器的
  （`policy_net.0` / `policy_net.2` / `action_net` + `log_std`），导出的 JSON 与
  `PolicyWeights` 同形，`mlpForwardMean` 直接跑。
- **观测不是契约**：23 维观测由 Python 定义、浏览器若要复用得自己重建一份 ——
  那正是「归一化口径写错不会让任何测试变红」的老坑。**fixture 带的是固定的观测向量**
  （策略真的遇到过的那些），前向传播因此可对拍；浏览器的**实时**观测构造留给下一轮，
  并且必须配自己的对拍。
- **训练会振荡**：40 000 步的运行里，最优的 checkpoint 出现在中段（step 29 500），
  之后反而变差 —— 与 Scene 3 同一个现象，所以**保留评估最优的 checkpoint** 是必须的，
  不是可选的。
- **顺手修了一个既有缺陷**：`network_sim_core.py` 的 Pure Pursuit alpha 符号与
  教科书相反（`heading - target_angle`），使转向**发散**。实测：需要转弯的 ego 直接
  开过路口，80 步后偏出路面 52 m、路线进度卡在 0.500。直线路段看不出来（目标在正前方，
  alpha≈0），所以既有测试从未抓到它。已修，并补了回归测试。

## Alternatives considered

- **全网每辆车都规划路线 / 都学习驾驶**（Scene 4 的完整版）：更真实，但协作信号被
  稀释（单个路口的协商只占全局很小比例），训练慢且难看出「协作真的发生」⇒ 拒绝：
  先把一个可测的子问题做扎实。
- **自博弈**（全部驾驶者都是学习者）：更接近「多智能体」，但自博弈不稳定、难归因 ⇒
  拒绝（本轮用脚本背景车）。
- **共享奖励（车队总延误）**：Scene 3 已实测这条路会塌缩（坍缩到即时收益最大的动作，
  −9068 对基线 −5391）⇒ 拒绝。
- **纯个人延误**（没有归因）：车只管自己 ⇒ 那不是协作 ⇒ 拒绝。
- **把枢轴改成弧线**：那才是枢轴碰撞的真正修法，但它是**模型改动**，而且会让
  「转进有车的路口」变得可预测 —— 本轮先把协商学出来，弧线留下一轮。
