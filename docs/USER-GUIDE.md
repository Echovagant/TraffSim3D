# TraffSim3D 用户指南

面向**使用这个平台的人** —— 想搭一个路口场景、跑一次仿真、把真实地图导进来、把智能体训出来的人。
不需要读源码。

> **开始之前**：本指南假设后端（FastAPI）与前端（Vite）已经启动。
> 启动步骤见 [`DEPLOYMENT.md`](DEPLOYMENT.md)。后端没起来时，地图导入、RL 训练、
> 后端状态页会失败，但场景编辑与仿真实验室仍可离线使用。

---

| Backend | `/backend` | 后端存活状态与端点自检 |

## 模块一：场景编辑器（SceneLab）

**路由 `/scene-editor`** —— 这是你的主工作台。

页面是全屏 3D 画布，顶部一条工具栏，左右分别是属性检查器与调试面板。

### 工具栏速查

| 按钮 | 作用 |
| --- | --- |
| `▶ 播放` / `⏸ 暂停` | 启动或暂停仿真时钟 |
| `−` / `+` | 降低 / 提升仿真速率 |
| `+ 车辆` | 在场景里加一辆车 |
| `🚗 +50 车辆` | 一次性生成 50 辆车 —— **用来演示碰撞**：密度过高时部分车会被撞成 `crashed` |
| `+ 信号灯` | 添加信号灯 |
| `🚨 全红` | 强制所有信号灯全红 3 秒（应急/演示用） |
| `重置` | 恢复到当前场景的初始状态 |
| **控制** 下拉 | 信号灯控制策略：固定 / 感应 / 协调（绿波带）/ RL（未实装，会回退到固定周期） |
| **场景** 下拉 | 切换演示场景：十字路口 / T 路口 / 矩形环 / 高架桥 / 多路口走廊 |
| `🚦 协调配置` | 仅在"协调"控制器下可用，弹窗设置绿波带偏移 |
| `↶ 撤销` / `↷ 重做` | 编辑历史回退 / 前进 |
| `🎯 适配场景` | 相机重新框住整个路网（相机跑飞后用这个救回来） |
| `🎯 聚焦` | 相机对准当前选中的实体 |
| `💾 保存` / `📂 加载` / `🗑️ 清除` | 场景存到浏览器 LocalStorage / 读回 / 删除 |
| `⬇ 导出` / `⬆ 导入` | 场景导出成 JSON 文件 / 从 JSON 文件导入 |
| `📥 轨迹 CSV` | 导出车辆轨迹（10 Hz 采样） |

> 从 MapLab 导入真实地图后，"场景"下拉会变成只读的 `📂 <文件名>` 标签。
> 想换回内置场景，直接在下拉里选任一内置场景即可放弃导入结果。

### 路线规划与第一人称视角

画布左上角有一个**路线规划**面板：

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 1 | 「起点车辆」选一辆车 | 路线从**这辆车所在的路上**开始算 —— 车正朝哪头去，起点就是那头 |
| 2 | 「终点路口」选一个路口 | 路线终点 |
| 3 | 点 `规划路线` | 后端按路网算最省路径，路线带画在路上，**这辆车按路线走** |

面板下方是驾驶读数：**目标路口 / 当前速度 / 路线进度 / 下一段路**。
勾上「**第一人称视角**」，相机就坐进车里 —— 眼高 1.35 m、看向前方 14 m，
你自己的车身不画（相机就在它里面）。

几点说明：

- **路线只对这一辆车生效**，其余车辆照常按信号与跟车规则跑。
- **单行道只能顺行**；路线不会让车逆行。
- **计划是建议**：车如果在路口没走成计划的那条路，会回到普通规则，
  进度条停在原处 —— 这是实况优先，不是出错。
- 换场景或导入新地图会清掉当前路线（它描述的是旧路网）。
- 路线规划需要**后端在线**（算路在服务端）；后端不在时面板会说明，其他功能照常。

### 键盘快捷键

| 按键 | 作用 |
| --- | --- |
| `Space` | 播放 / 暂停 |
| `Delete` / `Backspace` | 删除当前选中的车辆或信号灯 |
| `R` | 重置场景 |
| `+` / `=` / `-` / `_` | 提高 / 降低仿真速率 |
| `Esc` | 取消选中 |
| `F` | 聚焦到选中实体 |
| `Shift + F` | 适配整个场景 |
| `Ctrl + Z` / `Ctrl + Shift + Z` | 撤销 / 重做 |
| `?` | 打开快捷键说明弹窗 |

> 在输入框或下拉框里打字时，快捷键不会抢按键 —— 焦点在输入框时按键正常输入。

### 典型流程

1. 选一个内置场景（十字路口最适合第一次上手）
2. 点 `+ 车辆` 加几辆车，或直接 `🚗 +50 车辆` 看碰撞效果
3. 在"控制"里换成**协调**，点 `🚦 协调配置` 试一次绿波带
4. 想看开车？左上角**路线规划**面板：选一辆车 + 终点路口 → `规划路线` → 勾**第一人称视角**
5. 满意了就 `💾 保存`，或 `⬇ 导出` 成 JSON 分享给别人
6. 切到**仿真实验室**看更详细的指标

## 模块二：仿真实验室（SimulationLab）

**路由 `/simulation-lab`** —— 场景编辑器的控制台，负责观察和调参。

页面分五张卡片：

### 1. 场景统计

切换演示场景（单路口 / 走廊 / T 型路口 / 矩形环 / 高架桥），并实时显示：
车辆数、信号灯数、交叉口数、道路数、**南北轴排队数**、**东西轴排队数**、变道中的车辆数、仿真 tick 计数。

> 南北/东西两条排队数是判断"信号配时是否合理"最直接的指标：
> 一边长队一边空，说明该调绿波偏移了。

### 2. 信号控制

| 控制器 | 行为 |
| --- | --- |
| 固定 | 固定周期放行 |
| 感应 | 有车到达才延长绿灯 |
| 协调（绿波带） | 相邻路口按偏移量联动，可点 `⚙ 配置偏移` 调参 |
| RL | 尚未实装，选择后回退到固定周期 |

表格逐灯显示：灯 ID、所属轴（NS/EW）、当前相位、**剩余秒数**（倒计时）。
`🚨 全红 3s` 强制全红。

### 3. 传感器

| 开关 | 说明 |
| --- | --- |
| LiDAR（16 线） | 16 线激光扫描，实时统计帧数 |
| LiDAR 点云渲染 | 把扫描结果画出来（更直观，也更吃性能） |
| 📷 Camera（PiP） | 画中画的第一人称视角 |
| ⬇ CSV | 导出轨迹（10 Hz 采样）到 CSV |

### 4. 性能

FPS（低于门槛时会标黄警告）、帧耗时平均值 / 最小值 / 最大值、仿真速率（`−` / `+` 调节）、播放状态。

### 5. 物理仿真接入前后的对照表

一张对照表说明"这个功能在物理仿真接入前后的差别" —— 比如接入前车辆只是沿车道直线走，
接入 Rapier 之后才有真实质量/摩擦与碰撞检测（相撞的车状态变为 `crashed`）。
第一次用平台时扫一眼这张表，能快速建立预期。

## 模块三：AI 演武场（AI Proving Ground）

**路由 `/ai-playground`** —— 训练强化学习智能体，并把训好的策略放回仿真里开车。

### 第一步：配置训练

| 控件 | 取值 | 说明 |
| --- | --- | --- |
| 步数 | 100 – 100000 | 总训练步数 |
| 设备 | 自动 / GPU / CPU | GPU 不可用时该项会被置灰；选"自动"由后端决定 |
| Agent 数 | 1 – 8 | 智能体数量，多个 agent 共享一套 PPO |
| 场景 | 单路口 / 走廊（2 路口）/ T 型路口 / 环形路口 | 对应后端的 `cross` / `corridor` / `t_junction` / `roundabout` |
| 独立训练 | 勾选框 | 每个 agent 用**各自独立**的 PPO 策略，而不是共享 |
| 课程学习 | 勾选框 | 由易到难自动推进场景，见术语表 |
| Dry-run | 勾选框 | **不真正训练**，只写一段模拟 reward 历史，用来验证链路通不通 |

点 `开始训练`。训练在**独立子进程**里跑，界面不会卡住。

> **没装 SB3/torch 也能点开始训练**：此时系统自动降级成 dry-run，曲线照样有数据。
> 详见 [`DEPLOYMENT.md` §9.4](DEPLOYMENT.md#94-没装-sb3--torch-时-rl-训练会怎样降级行为)。

### 第二步：读指标

- **训练指标**：总步数、episode 数、agent 数、最近 reward、最新 checkpoint、运行状态
- **Reward 曲线**：横轴 episode，纵轴 reward。勾了"独立训练"时会**每个 agent 一条彩色折线**，
  便于对比各自的学习效果
- **Checkpoints**：列出 `名称 · 进程目录 · 大小 KB · 修改时间`
  - `列出 checkpoints` 手动刷新
  - `清理旧 checkpoints` 只保留最新的 5 个

### 第三步：策略部署（权重回放）

这是把训练成果"看见"的关键步骤：

1. 在 `Checkpoint` 下拉里选一个训练产物
2. 点 `加载` —— 前端向后端要这份权重的 JSON 表示，成功后显示
   `✓ 已加载 <名称> (14 obs / 2 act)`
3. 在 `目标车辆` 里选一辆车
4. 点 `▶ 开始回放` —— **这辆车改由训练好的策略驾驶**，你能在场景编辑器里看它怎么开车
5. `⏸ 停止` 结束回放；`清除` 卸载策略

展开"最近 obs / action"可以看到策略每一步实际吃到的观测向量和输出的动作。
观测向量是 **14 维**（这是前后端共同遵守的契约，见
[`contracts/sim-snapshot.md`](contracts/sim-snapshot.md)）。

## 模块四：地图导入（MapLab）

**路由 `/map-importer`** —— 把真实世界的路网导进来，直接驱动场景编辑器。

流程是 ① 取数据 → ② 上传。

### ① 在 Overpass Turbo 导出 `.osm`

页面提供 4 个现成查询模板：**天安门（北京）**、**福田中心（深圳）**、**南山（深圳）**、
**陆家嘴（上海）**。每个都限定了 `highway` 类型并排除了 `area=yes`，同时单独取出
`highway=traffic_signals` 节点（也就是红绿灯）。

点 `复制查询` 或 `在 Overpass Turbo 打开 ↗`，然后在 Overpass Turbo 里：

1. 点 **Run**
2. 右上角 **Export → Raw OSM data**
3. 保存为 `.osm` 文件

> **⚠ 注意默认裁剪**：不填裁剪边界时，后端只保留距数据中心的 **0.5°**（约 55 km）以内的节点。
> 这是**内存安全上限**，**不是**按你要仿真的区域裁剪 —— 导进来的数据可能被切掉一大块。
> 要精确裁剪，请做下一步。

### ② 上传 `.osm` 文件

1. 勾选 `启用裁剪 — 只加载仿真区域`，填入四个边界值：
   `south 南` / `west 西` / `north 北` / `east 东`（十进制度，可填小数）
2. 选择刚保存的 `.osm` 文件
3. 点 `上传并载入`

上传成功后页面显示统计：**道路数 / 路口数 / 红绿灯数**，并提示后端地址。

**不想裁剪**就不勾选那个开关，直接上传即可（会走 0.5° 上限）。
四个边界必须**同时**填或同时不填，只填一部分会被拒绝（HTTP 422，提示缺哪几个）。
`south` 必须 ≤ `north`，`west` 必须 ≤ `east`。

解析结果支持桥梁/隧道（`level` 标签）、单行道（`oneway`）、以及 `traffic_signals` 节点。
真实城市的大文件用 `.osm.pbf` 格式，选择文件时同样接受。

### 示例 fixture

不想连 Overpass？点 `载入示例 fixture`，直接载入仓库自带的
`tests/e2e/fixtures/sample-4way.osm`（4 路口 + 1 高架桥段）。

都必须保留这条署名。**

## 附加视图

### SmartCity 3D（`/smart-city`）

在真实城市底图上叠加仿真。Cesium 渲染底图（高德瓦片 + OSM 3D 拉伸建筑 + 道路多段线），
车辆、信号灯、LiDAR 画在透明的三维图层上，两者共用同一套仿真状态。

- **视图模式**：鸟瞰（1500 m）/ 平视（1.7 m 人眼高度）/ 自由
- 右上角面板：帧率、车辆数、灯数、平均速度、信号控制方式、仿真 tick、运行状态
- RL 回放活跃时，面板会多出一行 `RL 回放 活跃 (step N)`
- 底图数据经后端缓存，重复查询直接从磁盘返回，不必每次联网

> 底图依赖外部瓦片服务，在部分网络环境下可能加载较慢或失败；此时仿真叠加层仍可工作。

### Backend（`/backend`）

后端状态页。它会**读取后端的 OpenAPI schema 自动发现端点**并逐个探活，
所以新增接口会自动出现在这个列表里，不需要改前端。

面板还显示客户端配置：Base URL、请求超时（3000 ms）、Vite 代理规则、代码位置。

### DeliveryLab（`/deliverables`）

交付物目录页，当前是占位状态。

## 术语表

### OSM 导入

OpenStreetMap 是一个开放的地形数据项目，路网以 `.osm`（XML 文本）或 `.osm.pbf`（二进制，
体积更小，真实城市文件都用这个）格式分发。本平台的导入流程是：

```
Overpass 查询 → 导出 .osm/.pbf → 上传到后端 → 解析成路网图 → 渲染进场景编辑器
```

后端把经纬坐标投影到以数据中心为原点的三维坐标系（x/z 平面，单位米，y 为高度），
所以导入后你会看到一片可以直接开车的路网，而不是贴在地形上的线条。

### 裁剪 bbox（边界框）

`bbox` 是一个矩形裁剪范围，四个值按 **south, west, north, east** 的顺序给出，
单位是十进制度。**顺序不能颠倒** —— 这是接口约定的顺序，少填或错序都会被拒绝。

两种用法：

- **不传** → 后端使用 0.5° 的内存安全上限（防止一份全国数据把内存吃光）
- **传入** → 只保留矩形内的数据，这才是真正的"只加载我要仿真的这一片区域"

### A\* 路径规划

导入的 OSM 路网会被转换成一张**图**：路口是节点，道路段是有向边（单行道只保留一个方向）。
A\* 是这张图上的最短路算法 —— 给定起点和终点，找出总代价最低的路线，启发函数用直线距离
（欧氏距离）。在本项目里，它决定了每辆车在路口该往哪拐。

> 技术细节：启发函数只有在"任何一条边的代价都不低于它自身几何长度"时才保证最优。
> 因此 A\* 被设置为**宁可慢也不返回次优路径**；测试里用 Dijkstra（`heuristic="zero"`）
> 作为对照基准来验证这一点。

### 课程学习（curriculum learning）

训练智能体时，从最简单的问题开始，做到了再自动升级到更难的场景，而不是一上来就扔最难的。

本平台的推进顺序（由易到难）：

```
cross（十字路口） → t_junction（T 型路口） → roundabout（环形路口） → corridor（走廊）
```

晋级判据是最近 20 个 episode 的表现达标（平均 reward 或成功率超过该场景的阈值）。
好处是早期训练有反馈，不容易陷入"什么都学不到"的死局。

### 权重回放（replay）

训练产出的不是一段录像，而是一组**网络权重**。回放指的是把这组权重加载进浏览器，
让真实策略实时输出动作、由仿真里的车辆执行 —— 于是你能亲眼看到智能体怎么开车。

过程：选 checkpoint → 加载权重 → 选一辆目标车 → 开始回放。
权重以 JSON 形式从后端导出（含网络结构信息：观测维度、动作维度、隐藏层大小）。
如果后端没装 SB3/torch，这个接口会返回 **HTTP 503**，这是预期的降级行为。

## 故障速查

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| 地图导入报 `Failed to fetch` | 后端没起 | 见 [`DEPLOYMENT.md` §9.6](DEPLOYMENT.md#96-前端报-failed-to-fetch) |
| 上传后道路数比预期少很多 | 没填裁剪边界，走了 0.5° 上限 | 勾选"启用裁剪"并填四个边界 |
| 上传提示 `bbox requires all four...` | 四个边界没填全 | 四个一起填，或都不填 |
| 点"开始训练"曲线没涨 | 没装 SB3/torch，已降级为 dry-run | 装 `--extra rl`，见 [`DEPLOYMENT.md` §4.3](DEPLOYMENT.md#43-可选依赖强化学习栈extra-rl约-2-gb) |
| "加载 checkpoint" 报 503 | 同上，没装 SB3/torch | 同上 |
| GPU 选项是灰的 | 没检测到可用 CUDA 或显存 < 2 GB | 选"自动"或 CPU |
| 暂停 / 恢复 / 终止 报 409 | 当前没有正在运行的训练 | 先点"开始训练" |
| 保存的场景不见了 | LocalStorage 被清 / 换了浏览器 | 用 `⬇ 导出` 存成 JSON 文件更保险 |
| 加了 50 辆车后 FPS 掉 | 车辆太多 | `重置` 恢复，或在仿真实验室关掉点云渲染 |
